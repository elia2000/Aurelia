# اسکریپت نصب

اسکریپت نصب (`songbird-deploy`) روش توصیه‌شده برای نصب و مدیریت Aurelle است. این یک ابزار تعاملی و مبتنی بر منو است که وابستگی‌ها، بیلدها، Nginx، گواهی‌نامه‌های SSL، پیکربندی محیط، مدیریت پایگاه داده و به‌روزرسانی‌ها را مدیریت می‌کند، تا مجبور نباشید آن مراحل را به‌صورت دستی اجرا کنید.

:::info

این اسکریپت برای Ubuntu (22.04+) هدف‌گذاری شده و به دسترسی root نیاز دارد (هنگامی که به‌عنوان root اجرا نشود، به‌طور خودکار از `sudo` استفاده می‌کند). برای راه‌اندازی‌های مبتنی بر Docker یا کاملاً دستی، به [نصب از طریق Docker](./Installation-Docker.md) و [نصب دستی](./Manual-Installation.md) مراجعه کنید.

:::

## اولین اجرا

این دستور تک‌خطی را روی سرور خود اجرا کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/elia2000/Aurelia/main/scripts/install.sh | bash
```

این دستور اسکریپت را دانلود می‌کند، منو را باز می‌کند و یک دستور سراسری `songbird-deploy` را نصب می‌کند. از آن پس، هر زمان که خواستید آن را با این دستور اجرا کنید:

```bash
songbird-deploy
```

## نصب بدون پرسش

دستور تک‌خطی بالا منو را باز می‌کند و به ترمینال نیاز دارد. برای اسکریپت‌های راه‌اندازی، cloud-init، CI یا `ssh host 'curl ... | bash'` (بدون `-t`) حالتی وجود دارد که چیزی نمی‌پرسد: هر پاسخ از یک flag، یک متغیر `AURELLE_*` یا مقدار پیش‌فرض می‌آید.

```bash
# روی IP سرور، با HTTP
curl -fsSL https://raw.githubusercontent.com/elia2000/Aurelia/main/scripts/install.sh | sudo env AURELLE_YES=1 bash

# روی یک دامنه، با گواهی Let's Encrypt
curl -fsSL https://raw.githubusercontent.com/elia2000/Aurelia/main/scripts/install.sh | sudo env AURELLE_YES=1 AURELLE_DOMAIN=chat.example.com AURELLE_EMAIL=you@example.com bash

# همان کار با flag به جای متغیر
curl -fsSL https://raw.githubusercontent.com/elia2000/Aurelia/main/scripts/install.sh | sudo bash -s -- --yes --domain chat.example.com --email you@example.com
```

`sudo env` متغیرها را به اسکریپت می‌رساند (در غیر این صورت `sudo` آن‌ها را حذف می‌کند). اگر root هستید `sudo` را بگذارید کنار. بدون `AURELLE_YES` و بدون ترمینال، اسکریپت بلافاصله متوقف می‌شود (کد خروج ۲) و همین دستور را چاپ می‌کند، به جای اینکه منتظر پاسخی بماند که کسی نمی‌تواند بدهد.

| متغیر | Flag | پیش‌فرض | معنی |
|---|---|---|---|
| `AURELLE_YES` | `-y`، `--yes` | `0` | روشن کردن حالت بدون پرسش. |
| `AURELLE_DOMAIN` | `--domain` | خالی | نام دامنه‌ها، جداشده با ویرگول. خالی یعنی سرویس‌دهی روی IP عمومی سرور. |
| `AURELLE_EMAIL` | `--email` | خالی | ایمیل تماس برای Let's Encrypt و اعلان‌های push. بدون آن certbot بدون ایمیل ثبت‌نام می‌کند (بدون هشدار انقضا). |
| `AURELLE_TLS` | `--tls` | `auto` | `auto` (برای دامنه HTTPS، برای IP خالی HTTP)، `certbot`، `selfsigned`، `files`، `http`. |
| `AURELLE_TLS_CERT`، `AURELLE_TLS_KEY` | `--tls-cert`، `--tls-key` | خالی | فایل‌های `fullchain.pem` و `privkey.pem` برای `AURELLE_TLS=files`. |
| `AURELLE_PUBLIC_IP` | `--ip` | تشخیص خودکار | IPv4 عمومی سرور، وقتی تشخیص داده نمی‌شود (NAT، نبود دسترسی خروجی). |
| `AURELLE_SERVER_PORT`، `AURELLE_WORKER_PORT` | `--server-port`، `--worker-port` | `5174`، `8080` | پورت برنامه و پورت worker رسانه. |
| `AURELLE_CLIENT_PORT` | `--client-port` | `80` (با TLS برابر `443`) | پورتی که nginx روی آن گوش می‌دهد. |
| `AURELLE_CALLS_RELAY` | `--calls-relay`، `--no-calls-relay` | در نصب جدید `1` | `1`، `0` یا `force`. به [رله‌ی تماس](#calls-relay) مراجعه کنید. |
| `AURELLE_DB` | ندارد | `sqlite3` | `sqlite3` یا `postgres` (با `AURELLE_POSTGRES_URL` یا یک PostgreSQL محلی). |
| `AURELLE_OWNER_USERNAME`، `AURELLE_OWNER_PASSWORD`، `AURELLE_OWNER_NICKNAME` | ندارد | خالی | ساخت حساب مالک اول. بدون آن‌ها خلاصه‌ی پایانی می‌گوید چطور بسازید. |
| `AURELLE_ACTION` | `--action` | `auto` | `auto` نصب می‌کند، یا اگر Aurelle نصب است به‌روزرسانی می‌کند؛ `install` یا `update` یکی را اجباری می‌کند. |
| `REPO_BRANCH` | `--branch` | شاخه‌ی پیش‌فرض مخزن | شاخه یا تگی که نصب و در به‌روزرسانی دنبال می‌شود. |
| `REPO_URL` | `--repo` | مخزن رسمی | نشانی Git برای نصب. |
| `AURELLE_BACKUP` | ندارد | `0` | مقدار `1` پیش از به‌روزرسانی از پایگاه داده پشتیبان می‌گیرد. |
| `AURELLE_RESTORE_BACKUP` | ندارد | خالی | فایل پشتیبان پایگاه داده برای بازگردانی در نصب جدید. |
| `AURELLE_APT_LOCK_WAIT`، `AURELLE_HEALTH_TIMEOUT`، `AURELLE_MIN_FREE_DISK_MB` | ندارد | `300`، `90`، `2048` | ثانیه‌های انتظار برای apt دیگر، ثانیه‌های انتظار تا پاسخ برنامه، فضای آزاد لازم دیسک به مگابایت (`0` بررسی را رد می‌کند). |

برای فهرست کامل، شامل متغیرهای `MIRROR_*` برای شبکه‌های محدودشده، `bash install.sh --help` را اجرا کنید.

مقدارها پیش از هر تغییری بررسی می‌شوند و مقدار نادرست اسکریپت را با کد خروج 2 و پیامی که نام متغیر را می‌گوید متوقف می‌کند. هیچ مقداری که می‌دهید هرگز به‌عنوان دستور اجرا نمی‌شود و به‌صورت یک خط تازه به فایل‌های ساخته‌شده اضافه نمی‌شود:

- `AURELLE_DOMAIN`: فقط نام میزبان (حرف، رقم، خط تیره، نقطه). `AURELLE_PUBLIC_IP`: یک نشانی IPv4.
- `AURELLE_EMAIL`: پیش از `@` حرف، رقم و `. _ + -` و پس از آن یک نام میزبان. نویسه‌هایی مانند `; | $ % # & < > ' "` پذیرفته نمی‌شوند.
- `AURELLE_POSTGRES_URL`: با `postgres://` یا `postgresql://` شروع می‌شود و فاصله، خط جدید، نقل‌قول، بک‌تیک یا بک‌اسلش ندارد. نویسه‌های ویژه‌ی گذرواژه را به‌صورت `%XX` بنویسید (مثلاً `@` را `%40`).
- پورت‌ها (`AURELLE_*PORT`): عدد صحیح از 1 تا 65535. برای رله، کمینه باید از بیشینه کمتر باشد.
- `REPO_BRANCH`: فقط حرف، رقم و `. _ - / +`؛ `REPO_URL` نباید با `-` شروع شود.
- `AURELLE_OWNER_*`: بدون خط جدید و نویسه‌ی کنترلی.

اسکریپت برای شما این کارها را انجام می‌دهد:

- منتظر package manager دیگر می‌ماند (سرور ابری تازه تا چند دقیقه پس از اولین بوت خودش `apt` اجرا می‌کند)، دانلود قطع‌شده را دوباره تلاش می‌کند و پیش از هر تغییر، فضای دیسک و حافظه را بررسی می‌کند.
- وابستگی‌ها را با `npm ci` نصب می‌کند (دقیقاً مطابق فایل‌های lock)، Node.js نسخه‌ی ۲۴٫۱۸ یا بالاتر را لازم دارد و بیلد قبلی کلاینت را تا ساخته شدن بیلد جدید نگه می‌دارد.
- هنگام شکست یک مرحله با پیام روشن متوقف می‌شود (کد خروج ۱). هر مرحله قابل تکرار است: علت را رفع کنید و همان دستور را دوباره اجرا کنید.
- هرگز صفحه را پاک نمی‌کند و رازها را در لاگ نمی‌نویسد (`/opt/songbird/logs/install.log` توکن‌ها، کلیدها و گذرواژه‌ها را پنهان می‌کند). خلاصه‌ی پایانی با نشانی ورود در انتهای خروجی می‌ماند.
- اگر گواهی صادر نشود سایت کار می‌کند: Aurelle روی HTTP اجرا می‌شود و اسکریپت با کد ۳ خارج می‌شود. دامنه باید به سرور اشاره کند و پورت ۸۰ باز باشد؛ آن را رفع کنید و همان دستور را دوباره اجرا کنید.

**کدهای خروج:** `0` انجام شد، `1` یک مرحله شکست خورد، `2` استفاده‌ی نادرست یا نبود ترمینال برای پرسش، `3` نصب شد اما گواهی TLS صادر نشد.

:::tip حساب مدیر اول

ثبت‌نام در مرورگر و ادعای نقش مالک در `/admin` به HTTPS نیاز دارد. در نصب HTTP ساده، `AURELLE_OWNER_USERNAME` و `AURELLE_OWNER_PASSWORD` را تنظیم کنید، یا مالک را از منو بسازید (**Manage Database**، **Create user**، نقش `owner`).

:::

## رله‌ی تماس (coturn) {#calls-relay}

تماس بین افراد در شبکه‌های مختلف (دیتای موبایل، فایروال‌های سخت‌گیر) به رله نیاز دارد. نصب بدون پرسش به‌طور پیش‌فرض یکی راه‌اندازی می‌کند؛ نصب تعاملی می‌پرسد (پیش‌فرض بله) و گزینه‌ی ۱۰ منو آن را روی سرور نصب‌شده راه‌اندازی می‌کند. این مرحله:

۱. `coturn` را از apt نصب می‌کند و `/etc/turnserver.conf` را می‌نویسد (دسترسی `640`، گروه `turnserver`). فایل با `# Managed by the Aurelle installer` شروع می‌شود و از [تماس‌ها و پیام‌های ویدیویی](./Calls-and-Video-Messages.md) پیروی می‌کند: اعتبارنامه‌های کوتاه‌عمر از یک راز مشترک، رد شبکه‌های خصوصی و خود سرور به‌عنوان مقصد رله، سهمیه‌ی هر کاربر.

۲. `CALLS_TURN_URLS` و `CALLS_TURN_SECRET` متناظر را در `.env` برنامه می‌نویسد (یک راز در هر دو طرف) و Aurelle را دوباره راه‌اندازی می‌کند.

۳. اگر `ufw` یا `firewalld` فعال باشد پورت‌های رله را در آن باز می‌کند. هرگز فایروالی را روشن نمی‌کند.

۴. رله را از خود سرور با `scripts/check-relay.sh` آزمایش می‌کند. شکست آزمایش هشدار است، نه شکست نصب: بقیه‌ی Aurelle کار می‌کند و خروجی می‌گوید چه چیزی را بررسی کنید.

نشانی رله وقتی دامنه مستقیم به سرور اشاره کند همان دامنه است، و در غیر این صورت IP سرور (پشت ابر نارنجی Cloudflare نام به Cloudflare ترجمه می‌شود که هرگز TURN را عبور نمی‌دهد). با دامنه و گواهی، رله روی `5349` هم با TLS گوش می‌دهد (`turns:`)؛ گواهی در `/etc/coturn/certs` کپی می‌شود و یک hook از certbot پس از هر تمدید آن را تازه می‌کند.

مقادیر `AURELLE_CALLS_RELAY`: `1` راه‌اندازی، `0` رد کردن، `force` جایگزینی پیکربندی coturn که این نصب‌کننده ننوشته (فایل قبلی با نام `/etc/turnserver.conf.bak.<timestamp>` می‌ماند). بدون `force`، coturn که کس دیگری تنظیم کرده یا `CALLS_TURN_URLS` از قبل تنظیم‌شده در `.env` دست‌نخورده می‌ماند. وقتی متغیر تنظیم نشده باشد، به‌روزرسانی پشت سر مالک رله نصب نمی‌کند؛ برای افزودن بعدی: `sudo env AURELLE_CALLS_RELAY=1 songbird-deploy --yes`. پورت‌ها را با `AURELLE_RELAY_PORT` (پیش‌فرض `3478`)، `AURELLE_RELAY_MIN_PORT` و `AURELLE_RELAY_MAX_PORT` (پیش‌فرض `49160` تا `49260`) تغییر دهید.

## پورت‌های فایروال

اسکریپت فقط در `ufw` یا `firewalld` فعال پورت باز می‌کند. فایروال خود ارائه‌دهنده‌ی ابری (security group) از دسترس آن خارج است: این پورت‌ها را آنجا خودتان باز کنید.

| پورت | پروتکل | کاربرد |
|---|---|---|
| `80` | TCP | سایت با HTTP، هدایت به HTTPS و بررسی گواهی. |
| `443` | TCP | سایت با HTTPS (دامنه، یا `AURELLE_TLS` غیر از `http`). |
| `3478` | TCP و UDP | رله‌ی تماس (STUN و TURN). |
| `49160` تا `49260` | UDP | رسانه‌ی رله‌ی تماس. |
| `5349` | TCP و UDP | رله‌ی تماس با TLS (`turns:`)، فقط وقتی رله گواهی دارد. |

برنامه (`5174`) و worker رسانه (`8080`) برای nginx و یکدیگر گوش می‌دهند و لازم نیست از بیرون در دسترس باشند.

## روند نصب

هنگامی که **Install** را انتخاب می‌کنید، اسکریپت شما را از طریق مجموعه‌ای از پرسش‌ها راهنمایی می‌کند:

### ۱. حالت منبع

| حالت | توضیح |
|---|---|
| GitHub | کلون‌کردن پروژه از مخزن رسمی GitHub. |
| Offline | نصب از یک فایل zip منبع محلی (برای سرورهای محدود شده مفید است). |

### ۲. حالت نصب

| حالت | توضیح |
|---|---|
| Domain | سرویس دهی Aurelle روی یک نام دامنه (مانند `example.com`). |
| IP | سرویس دهی مستقیم Aurelle روی IP عمومی سرور. |

### ۳. حالت گواهینامه

| حالت | توضیح |
|---|---|
| Obtain certificate | درخواست خودکار گواهینامه. برای دامنه ها از Certbot (Let's Encrypt) استفاده میکند؛ برای IPها یک گواهینامه کوتاه مدت ۶ روزه از طریق `lego` درخواست میکند. |
| TLS certificate files | استفاده از فایل های `fullchain.pem` و `privkey.pem` موجود خودتان. |
| HTTP only | رد کردن TLS و سرویس دهی روی HTTP ساده. |
| Self-signed certificate | تولید یک گواهینامه خودامضاشده (Self-signed). توصیه نمیشود. |

:::info

HTTPS برای اعلان های Push الزامی است (به جز روی `localhost`). اگر میخواهید Push کار کند، حالتی غیر از HTTP only را انتخاب کنید.

:::

### ۴. انتخاب موتور پایگاه داده

| گزینه | توضیح |
|---|---|
| SQLite (پیشفرض) | پایگاه داده SQLite در حافظه با ماندگاری ناهمگام روی دیسک (`better-sqlite3`). مناسب برای نمونه های کوچک تا متوسط. |
| PostgreSQL | موتور پایگاه داده خارجی PostgreSQL. برای نمونه های بزرگتر (+۵۰۰ کاربر) توصیه میشود. مشخصات میزبان PostgreSQL، پورت، نام پایگاه داده، نام کاربری و رمز عبور را میپرسد. |

### ۵. پرسش های محیط

در حین نصب، اسکریپت تنظیمات اصلی را می‌پرسد و آن‌ها را در `.env` می‌نویسد:

| پرسش | متغیر محیطی | پیش‌فرض |
|---|---|---|
| پورت سرور | `SERVER_PORT` | `5174` |
| پورت کلاینت | `CLIENT_PORT` | `80` |
| پورت Media Worker | `WORKER_PORT` | `8080` |
| ایمیل برای اطلاعیه‌های Let's Encrypt (حالت certbot) | — | — |

کلیدهای رمزنگاری و push نوتیفیکیشن (`STORAGE_ENCRYPTION_KEY`، `VAPID_*`) به‌طور خودکار تولید می‌شوند. فهرست کامل متغیرهایی که می‌توانید بعداً تنظیم کنید در [متغیرهای محیطی](./Environment-Variables.md) قرار دارد.

### ۶. ایجاد کاربر مالک در اولین اجرا

پس از تکمیل نصب و شروع سرویس، در اولین دسترسی از شما خواسته می‌شود که یک کاربر مالک ایجاد کنید. این حساب مالک دسترسی کامل به پنل مدیریت برای مدیریت کاربران، چت‌ها و تنظیمات سیستم دارد. برای جزئیات به [پنل مدیریت](./Admin-Panel.md) مراجعه کنید.

## زیرمنوی پایگاه داده

گزینه **۵** یک مدیر کامل پایگاه داده را باز می‌کند که [دستورات پایگاه داده](./Database-Commands.md) را با پرسش‌های راهنمایی‌شده می‌پوشاند، بنابراین نیازی به به‌خاطر سپردن پرچم‌ها ندارید:

| گروه | اقدام‌ها |
|---|---|
| Inspect | خلاصه پایگاه داده، چت‌ها، کاربران، فایل‌ها |
| Backup & Repair | پشتیبان‌گیری، بازیابی، vacuum، بازنشانی، حذف |
| User & Chat Management | ایجاد کاربر، تولید کاربران، ویرایش کاربر، مسدود/رفع‌مسدود، ایجاد گروه/کانال، افزودن اعضا، ویرایش چت |
| Remote Channels | پیکربندی کانال ریموت |
| Destructive Actions | حذف چت‌ها، حذف کاربران، حذف فایل‌ها |
| Help & Navigation | نمایش راهنما، بازگشت، خروج |

## به‌روزرسانی و دانگرید

از منوی اصلی گزینه **Update Aurelle** (گزینه ۲) را برای به روزرسانی یا دانگرید نمونه خود انتخاب کنید:

۱. **پشتیبان گیری از پایگاه داده**: اسکریپت پیش از تغییر فایل های برنامه، پیشنهاد ایجاد یک نسخه پشتیبان با برچسب زمانی را میدهد.

۲. **حالت GitHub**:

   - **به روزرسانی**: اگر شاخه یا تگی که نصب دنبال می‌کند (`REPO_BRANCH`، وگرنه شاخه‌ی پیش‌فرض مخزن) کامیت جدیدتری داشته باشد، اسکریپت checkout را به آن منتقل می‌کند، وابستگی ها را (`npm ci`) نصب، مهاجرت های دیتابیس را اعمال، کلاینت را بازسازی و سرویس ها را مجدداً راه اندازی میکند. نخست از منبع می‌پرسد: اگر در دسترس نباشد چیزی متوقف یا تغییر داده نمی‌شود.
   - **دانگرید**: اگر مخزن از قبل به روز باشد، پیام `Do you want to downgrade? [y/N]` نمایش داده میشود. در صورت تأیید، میتوانید هر نسخه معتبری را مشخص کنید (تگ نسخه بندی معنایی مانند `v0.11.4`، تگ سفارشی، شاخه یا هش کامیت). اسکریپت آن مرجع را checkout کرده، مهاجرت ها را انجام میدهد و پروژه را بازسازی میکند.

۳. **حالت آفلاین**:

   - **به روزرسانی**: اگر فایل `VERSION` درون آرشیو zip جدیدتر از نسخه نصب شده باشد، فایل ها را به روزرسانی و پروژه را مجدداً بازسازی میکند.
   - **دانگرید**: اگر مقدار `VERSION` درون آرشیو یکسان یا قدیمی تر از نسخه نصب شده باشد، پیش از دانگرید از شما تأییدیه میگیرد.

برای جزئیات کامل و روش های دستی به [به‌روزرسانی و دانگرید](./Updating.md) مراجعه کنید.

### به‌روزرسانی بدون پرسش

اجرای دوباره‌ی دستور تک‌خطی روی سروری که Aurelle دارد آن را به‌روزرسانی می‌کند (مثل `AURELLE_ACTION=update`)، و پس از نصب دستور سراسری `songbird-deploy --yes` هم همین کار را می‌کند:

```bash
sudo songbird-deploy --yes
# یا بدون دستور سراسری
curl -fsSL https://raw.githubusercontent.com/elia2000/Aurelia/main/scripts/install.sh | sudo env AURELLE_YES=1 bash
```

- اگر از قبل جدیدترین نسخه است: چیزی تغییر نمی‌کند (نبود بیلد کلاینت یا برنامه‌ای که پاسخ نمی‌دهد ترمیم می‌شود و سرویس‌ها دوباره شروع می‌شوند).
- `.env` شما حفظ می‌شود، از جمله تنظیماتی که نصب‌کننده ننوشته (مثل `CALLS_TURN_URLS`). به‌روزرسانی دسترسی `.env` را هم به `640` محدود می‌کند (این فایل کلید رمزنگاری، توکن مدیر و راز رله را دارد).
- `AURELLE_BACKUP=1` پیش از به‌روزرسانی از پایگاه داده پشتیبان می‌گیرد. اگر به‌روزرسانی پیش از راه‌اندازی مجدد Aurelle پایان یابد، اسکریپت نسخه‌ی قبلی را دوباره شروع می‌کند، نه اینکه سایت را خاموش بگذارد.
- دادن دامنه، حالت TLS یا پورتی متفاوت با نصب فعلی، نصب را پیکربندی مجدد می‌کند (nginx، گواهی) و فقط به‌روزرسانی نمی‌کند.
- رله‌ی تماس فقط وقتی `AURELLE_CALLS_RELAY` تنظیم شده باشد تغییر می‌کند.

## به روزرسانی منوی اسکریپت

برای به روزرسانی خودِ اسکریپت `songbird-deploy`، گزینه **Update menu** (گزینه ۷) را انتخاب کنید:

۱. **بررسی به روزرسانی ها**: اسکریپت به مخزن رسمی GitHub متصل میشود تا بررسی کند آیا نسخه جدیدتری از `scripts/install.sh` موجود است یا خیر.

۲. **به روزرسانی خودکار**: در صورت وجود نسخه جدیدتر، به طور خودکار آن را دانلود کرده و دستور سراسری `songbird-deploy` (`/usr/local/bin/songbird-deploy`) را به آخرین نسخه به روزرسانی میکند.

۳. **درخواست نصب مجدد**: اگر منو از قبل به روز باشد، یا در صورتی که بررسی GitHub با خطا مواجه شود (برای مثال در شبکه های دارای محدودیت اتصال)، این پیام نمایش داده میشود:

   ```txt
   Do you want to reinstall the current menu again? [y/N]
   ```
   انتخاب `yes` دستور سراسری را با استفاده از اسکریپت محلی فعلی مجدداً نصب میکند.

## mirrorها برای شبکه‌های محدودشده

اگر سرور شما دسترسی محدودی به منابع پیش‌فرض بسته‌ها دارد، از **Configure mirrors** برای تنظیم موارد زیر استفاده کنید:

| mirror | هدف |
|---|---|
| NodeSource mirror | منبع جایگزین برای راه‌اندازی apt مربوط به Node.js. |
| apt mirror source | mirror اضافه apt برای بسته‌های پایه. |
| npm registry mirror | رجیستری جایگزین npm برای نصب وابستگی‌ها. |

همچنین می‌توانید از همان منو پیش‌فرض‌ها را بازگردانی کنید (پاک‌کردن همه mirrorها).

:::tip

می‌توانید از این mirrorها در محیط محدودشده ایران استفاده کنید:
- NodeSource:
```
https://mirror-nodejs.runflare.com/dist/v24.18.0/node-v24.18.0-linux-x64.tar.gz
```
- APT:
```
http://ubuntu.pars.host/ubuntu/
```
- NPM:
```
https://package-mirror.liara.ir/repository/npm/
```

:::

## لاگ‌ها

زیرمنوی **View Logs** مفیدترین لاگ‌ها را بدون نیاز به به‌خاطر سپردن مسیرها در دسترس قرار می‌دهد:

| گزینه | منبع |
|---|---|
| Script logs | لاگ خود نصاب در `/opt/songbird/logs/install.log`. |
| Service logs | خروجی `journalctl` برای `songbird.service`. |
| Nginx access logs | لاگ دسترسی Nginx. |
| Nginx error logs | لاگ خطای Nginx. |
